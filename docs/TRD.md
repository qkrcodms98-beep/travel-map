# TRD - 나만의 여행 지도 (초안)

> 기준 문서: [IDEA.md](IDEA.md), [PRD.md](PRD.md). 이 문서와 IDEA.md가 다르면 IDEA.md를 따른다.
> 범위: v0.1 ~ v1.0. 기능 ID(F-01 등)는 PRD.md를 따른다.

## 1. 용어 설명

| 용어 | 뜻 |
|---|---|
| 브라우저 메모리 | 화면을 띄운 브라우저 탭 안에만 기록을 들고 있는 것. 새로고침하면 사라진다 (v0.1) |
| 서버 | 화면에 데이터를 주고받는 쪽 프로그램 |
| 프런트엔드 | 화면 쪽 프로그램. 여기서는 Next.js가 맡고, 화면만 그린다 |
| 백엔드 | API와 저장을 맡는 서버 프로그램. 여기서는 `backend/` 폴더의 FastAPI가 맡는다 (v0.2부터) |
| 서버 메모리 | 서버 프로그램이 켜져 있는 동안만 기록을 들고 있는 것. 서버를 끄면 사라진다 (v0.2) |
| API | 화면이 서버에 "이 여행 저장해 줘", "목록 줘"라고 부탁하는 정해진 주소와 약속 |
| DB (데이터베이스) | 기록을 컴퓨터의 저장 장치(디스크)에 저장해 두는 곳. 서버를 꺼도 남는다 (v0.3) |
| Neon | 인터넷에서 빌려 쓰는 Postgres DB 서비스 |
| 배포 | 내 컴퓨터가 아니라 인터넷 서버에 앱을 올려 누구나 주소로 접속할 수 있게 하는 것 (v1.0) |
| 경계 데이터 | 시·군·구, 읍·면·동의 모양(테두리 좌표)을 담은 파일 |
| GeoJSON / TopoJSON | 경계 데이터 파일 형식. TopoJSON은 이웃 지역이 맞닿은 선을 한 번만 저장해서 GeoJSON보다 훨씬 작다 |
| App Router | Next.js에서 `app/` 폴더 구조대로 페이지 주소가 정해지는 방식 |
| strict | TypeScript의 가장 엄격한 검사 모드. 빠뜨린 값이나 애매한 타입도 오류로 알려 준다 |
| ORM | DB 표를 코드 속 데이터처럼 다루게 해 주는 도구. DB 명령어(SQL)를 직접 쓰지 않아도 된다 |
| React state | 화면이 기억하고 있는 값. 값이 바뀌면 화면이 다시 그려진다 |
| POST | API에 "새로 만들어 줘"라고 부탁하는 방식. "가져와 줘"는 GET이다 |
| 여행 저장소 | 여행을 저장하고 불러오는 코드를 한 곳에 모은 것. 저장 위치(메모리, DB)가 바뀌어도 이 부분만 고친다 |
| WGS84 좌표 | GPS와 같은 위도·경도 좌표 방식 |
| shp | 지도 프로그램(QGIS 등)에서 쓰는 경계 파일 형식. 웹에서 쓰려면 다른 형식으로 바꿔야 한다 |
| KOSTAT | 통계청의 영어 약자 |
| CC BY 4.0 | 출처만 밝히면 자유롭게 쓰고 고칠 수 있는 라이선스 |
| 공공누리 1유형 | 공공기관 자료의 이용 조건. 출처만 밝히면 고치거나 상업적으로 써도 된다 |
| FastAPI | 파이썬으로 API 서버를 만드는 도구 |
| Pydantic | 파이썬에서 들어온 데이터의 모양(필드, 타입)을 검사하는 도구. FastAPI가 함께 쓴다 |
| uv | 파이썬 버전과 패키지(라이브러리)를 설치·관리하는 도구. npm과 비슷한 역할 |
| pytest / TestClient | 파이썬 테스트 도구 / 서버를 진짜로 켜지 않고 API를 불러 볼 수 있게 해 주는 FastAPI 도구 |
| SQLAlchemy | 파이썬용 ORM (v0.3) |
| Alembic | DB 표의 모양이 바뀔 때 그 변경을 순서대로 기록하고 적용하는 도구 (v0.3) |
| psycopg | 파이썬이 Postgres DB에 연결할 때 쓰는 연결 도구 (v0.3) |
| camelCase / snake_case | 이름 붙이는 방식. `startDate`처럼 단어 첫 글자를 대문자로 / `start_date`처럼 밑줄로 잇는다 |
| 타입 힌트 | 파이썬에서 변수와 함수의 값 종류를 적어 두는 것. TypeScript의 타입과 비슷하다 |
| 환경 변수 | 코드 밖(`.env` 파일 등)에 두는 설정 값. 주소나 비밀번호처럼 코드에 적으면 안 되는 값을 넣는다 |
| CORS | 브라우저가 다른 주소(예: 3000번 → 8000번)의 서버를 부를 때, 그 서버가 허락했는지 확인하는 규칙 |
| 의존성 주입 (dependency) | FastAPI에서 "지금 시각", "저장소" 같은 재료를 바깥에서 넣어 주는 방식. 테스트에서 가짜로 바꿔 끼울 수 있다 |

## 2. 기술 스택과 고른 이유

### 프런트엔드 (화면)

| 기술 | 고른 이유 |
|---|---|
| Next.js 15 (App Router) | `app/` 폴더 구조대로 화면 주소가 정해져서 화면을 나눠 만들기 쉽다. **화면만 맡고 API 라우트(`app/api`)는 만들지 않는다** |
| React 19 | 화면을 "지도", "여행 목록"처럼 작은 조각(컴포넌트)으로 나눠 만들 수 있다 |
| TypeScript (strict) | 값의 종류(날짜인지, 글자인지)를 미리 적어 두면 실수를 실행 전에 잡아 준다 |
| Tailwind CSS | 스타일을 따로 파일로 만들지 않고 태그에 바로 적어서, 휴대폰·컴퓨터 화면 크기 대응을 쉽게 한다 |
| d3 | 경계 좌표를 화면 위 지도 모양으로 그려 주고, 확대·이동(F-16)도 지원한다 |
| topojson-client | 작게 줄인 TopoJSON 파일을 d3가 그릴 수 있는 모양으로 풀어 준다 |
| Zod | "시작일은 오늘까지", "일기는 2,000자까지" 같은 입력 규칙을 화면의 폼에서 먼저 검사한다. 서버 검사는 백엔드가 따로 한다 |
| Jest + React Testing Library | 계산 함수(색칠, 여행 번호, 완성도)와 화면이 규칙대로 동작하는지 자동으로 확인한다 |

### 백엔드 (API와 저장, v0.2부터)

| 기술 | 고른 이유 |
|---|---|
| Python 3.12 | 백엔드를 화면과 다른 언어로 따로 만들어 보며 배우기 위해서다. 타입 힌트로 값의 종류를 적을 수 있다 |
| uv | 파이썬 버전과 패키지를 한 도구로 설치하고, 설치한 버전을 파일(`uv.lock`)로 남겨 다시 똑같이 설치할 수 있다 |
| FastAPI | 주소별로 함수 하나를 붙이면 API가 된다. 타입 힌트를 그대로 검사에 쓴다 |
| Pydantic v2 | 요청 JSON의 모양(필드, 타입, 모르는 필드)을 검사하고, camelCase ↔ snake_case 이름을 바꿔 준다 |
| pytest + FastAPI TestClient | 검사 함수와 API 4개를 서버를 켜지 않고 자동으로 확인한다 |
| Postgres (Neon) | 여행 기록을 안전하게 오래 저장한다. Neon은 설치 없이 무료로 시작할 수 있다 (v0.3) |
| SQLAlchemy 2.0 | DB 표를 파이썬 코드로 적고, 타입 힌트와 함께 DB를 읽고 쓸 수 있다 (v0.3) |
| Alembic | DB 표를 만들거나 바꾼 기록을 파일로 남겨, 같은 순서로 DB에 적용한다 (v0.3) |
| psycopg | 파이썬에서 Postgres에 연결한다 (v0.3) |

## 3. 버전별 구조

| 버전 | 기록 저장 위치 | 화면이 기록을 읽고 쓰는 방법 |
|---|---|---|
| v0.1 | 브라우저 메모리 | 화면 안의 상태(React state)를 직접 바꾼다 |
| v0.2 | 백엔드 서버 메모리 | FastAPI 백엔드의 API를 부른다. 백엔드는 메모리 안의 목록에 저장한다 |
| v0.3 ~ | DB (Neon) | FastAPI 백엔드의 API를 부른다. 백엔드는 SQLAlchemy로 DB에 저장한다 |

- v0.2에서 화면 → API 연결을 먼저 만들어 두고, v0.3에서는 백엔드 안의 저장 부분만 DB로 바꾼다. 화면 코드는 그대로 둔다
- 화면 쪽: v0.2에서 `TripStoreProvider`가 브라우저 메모리 대신 백엔드 API를 부르도록 바뀐다. 페이지와 부품은 고치지 않는다 (COMPONENT_SPEC 3-1)
- 백엔드 쪽: 저장 부분은 `backend/app/`의 "여행 저장소" 하나로 모아 두어, 메모리 → DB로 바꿀 때 이 부분만 고친다

### 프런트엔드와 백엔드

```
브라우저 ── 화면 ──▶ Next.js (localhost:3000)
   │
   └── API 요청 (JSON) ──▶ FastAPI (localhost:8000) ──▶ 메모리 (v0.2) / Neon DB (v0.3~)
                               └─ 지역 코드 검사: public/data/codes.json 읽기
```

- 두 프로그램은 따로 켠다. 개발할 때는 터미널 두 개에서 각각 실행한다 (CLAUDE.md "자주 쓰는 명령")
- 화면은 `NEXT_PUBLIC_API_URL`(개발: `http://localhost:8000`) 뒤에 API_SPEC의 주소를 붙여 부른다. 예: `http://localhost:8000/api/trips`
- 주소가 달라서(3000번 → 8000번) 브라우저가 CORS 확인을 한다. 백엔드는 프런트 주소만 허락한다 (7장)

### 백엔드 폴더 구조 (처음 계획)

```
backend/
├─ pyproject.toml   패키지 목록 (uv가 관리)
├─ uv.lock          설치한 정확한 버전
├─ app/
│  ├─ main.py       FastAPI 앱 만들기, CORS, 에러 모양 맞추기 (8장)
│  ├─ routes.py     API 주소 4개 (API_SPEC 3장)
│  ├─ schemas.py    Pydantic 모델: 요청·응답 모양, camelCase 이름
│  ├─ rules.py      입력 검사 (API_SPEC 5장 순서), 글자 세기, 한국 날짜
│  ├─ codes.py      codes.json 읽기
│  └─ store.py      여행 저장소 (v0.2 메모리, v0.3 DB)
└─ tests/           pytest 테스트, 가짜 코드 목록
```

- 파일이 커지면 나눌 수 있지만, 역할(검사·저장소·주소)은 섞지 않는다

## 4. 지역을 눌러 여행을 저장하기까지의 흐름

v0.3 이후 기준이다. v0.1은 2~3단계 대신 화면 안의 상태에 바로 넣고, v0.2는 3단계에서 DB 대신 서버 메모리에 넣는다.

### 1단계: 화면 (첫 화면 → 지역 화면 → 새 여행 기록 화면)
1. 첫 화면에서 `public/data/`의 시·군·구 경계 파일을 불러와 d3로 지도를 그린다 (F-01)
2. 각 지역의 여행 횟수로 색을 정한다. 색은 계산 함수가 정한다 (F-08)
3. 사용자가 지역을 누르면 그 지역의 코드(예: 대구 군위군 `27720`)를 가지고 지역 화면으로 이동한다 (F-02)
4. 지역 화면에서 새 여행 기록 화면으로 이동해 시작일, 종료일, 여행일기를 입력한다 (F-03)
5. (v0.4부터) 같은 화면에서 그 지역의 동네(행정동)를 여러 개 고른다. 동네 목록은 읍·면·동 경계 파일에서 가져온다 (F-11)
6. 저장을 누르면 Zod로 입력 규칙을 먼저 검사한다. 어기면 저장하지 않고 안내 문구를 보여 준다

### 2단계: API (화면 → FastAPI 백엔드)
7. 화면이 백엔드에 여행 저장을 부탁한다. 예: `POST {NEXT_PUBLIC_API_URL}/api/trips` + 지역 코드, 시작일, 종료일, 여행일기, 동네(v0.4부터) (자세한 주소와 형식은 API_SPEC.md에서 정한다)
8. 백엔드도 같은 규칙으로 한 번 더 검사한다. Pydantic으로 모양을 보고, 파이썬 검사 함수로 날짜·일기·코드를 API_SPEC 5장 순서대로 본다. 화면 검사를 건너뛰고 들어온 잘못된 값을 막기 위해서다
   - 화면(Zod)과 백엔드(파이썬)는 코드를 같이 쓸 수 없어서 규칙을 두 번 적는다. 두 곳이 어긋나지 않게 TEST_CASES의 VAL 표 하나로 양쪽을 각각 테스트한다
9. 규칙을 어기면 오류 응답을 돌려주고, 화면이 안내 문구를 보여 준다

### 3단계: DB (백엔드 → Neon)
10. 백엔드가 SQLAlchemy로 여행 한 줄을 DB에 저장한다. 기록한 시각도 함께 저장한다 (같은 시작일의 순서를 정하는 데 쓴다)
11. 저장이 끝나면 백엔드가 저장한 여행 하나를 돌려준다 (API_SPEC.md 3-2)

### 다시 화면으로
12. 화면이 그 지역의 여행 목록을 다시 받아 여행 번호를 계산하고(F-07), 최신순으로 보여 준다(F-02)
13. 첫 화면으로 돌아가면 바뀐 여행 횟수로 지도 색이 다시 칠해진다 (F-08)

### 여행 번호를 DB에 저장하지 않는 이유
- 여행 번호는 저장하지 않고 읽을 때마다 계산 함수로 매긴다
- 이렇게 하면 날짜를 고치거나 여행을 지워도 번호가 저절로 다시 맞는다 (F-07)

## 5. 계산 함수

CLAUDE.md 규칙에 따라 아래 계산은 화면과 떨어진 함수로 `src/lib/`에 두고 테스트한다. 여행 번호, 정렬, 색칠, 완성도는 화면에서만 계산하므로 백엔드에는 만들지 않는다 (API_SPEC 4장).

| 함수 | 하는 일 | 버전 |
|---|---|---|
| 여행 번호 | 시작일 순서로 번호 매기기. 시작일이 같으면 먼저 기록한 여행이 앞 번호 | v0.1 |
| 목록 정렬 | 최신순(시작일 기준). 시작일이 같으면 나중에 기록한 여행이 위 | v0.1 |
| 방문 횟수 | 지역별 여행 개수 세기 | v0.1 |
| 색칠 단계 | 0번 흰색, 1번 연두색, 2번 이상 진한 초록 (v0.4부터 지형 무늬) | v0.1 |
| 지도 완성도 | 가 본 시·군·구 넓이 ÷ 전체 땅 넓이. 소수 첫째 자리까지 버림, 모든 지역을 가 봤을 때만 100% | v0.4 |
| 글자 세기 | 여행일기 글자 수 세기 (`countDiaryChars`). 화면의 남은 글자 수와 폼 검사에 쓴다 | v0.1 |
| 구 합치기 | 시·군·구 코드를 합친 시 코드로 바꾸기. 코드 목록 파일을 만들 때 쓴다 (6장) | v0.1 |

### 백엔드에도 따로 두는 함수 (`backend/app/`)

서버 검사에 필요한 두 가지는 파이썬으로 다시 만든다. 화면 쪽 함수와 **같은 테스트 값**으로 확인해서 결과를 맞춘다 (TEST_CASES BE 묶음).

| 함수 | 하는 일 | 화면 쪽 짝 | 버전 |
|---|---|---|---|
| `count_diary_chars` | 문자 하나를 1자로 센다. 파이썬 `len()`이 이미 이렇게 세므로 그대로 쓴다 (😀 = 1자, DB와 같음) | `countDiaryChars` | v0.2 |
| `today_in_seoul` | 받은 시각을 한국 시간(Asia/Seoul) 날짜로 바꾼다 | `getTodayInSeoul` | v0.2 |

### 쓰는 방법
- 원본(약 33MB)은 그대로 쓰지 않는다. 모양을 단순하게 줄이고(점 개수를 줄여 파일을 가볍게 하고) TopoJSON으로 바꿔 `public/data/`에 둔다
- 파일은 두 개로 나눈다
  - 시·군·구 파일: 첫 화면 지도용 (v0.1). 읍·면·동을 시·군·구 코드로 합쳐서 만든다
  - 읍·면·동 파일: 동네 선택용 (v0.4)
- 서버는 코드 검사를 위해 지도 데이터를 읽는다 (API_SPEC.md 5장)
  - 서버용으로는 모양 없이 코드와 이름만 담은 가벼운 **코드 목록 파일**을 따로 만든다. 지도 파일과 같은 원본에서 같이 만든다
  - 담는 내용: 시·군·구 코드와 이름(구를 합친 뒤), 동네 코드와 이름, 그 동네가 속한 시·군·구 코드 (동네는 v0.4부터)
  - 화면도 지역 이름·동네 이름을 보여 줄 때 이 파일을 쓴다 (COMPONENT_SPEC.md)
  - 서버가 모양까지 담긴 지도 파일을 읽지 않아도 되어 가볍고, 화면과 서버가 같은 원본에서 나온 코드를 쓴다
  - FastAPI 백엔드도 이 파일(`public/data/codes.json`)을 그대로 읽는다. `backend/` 바깥에 있으므로 파일 위치는 백엔드 설정으로 정하고, 기본값은 `backend/`에서 본 `../public/data/codes.json`이다
  - 백엔드는 켜질 때 한 번만 읽어 둔다. 테스트에서는 같은 모양의 가짜 코드 목록(TEST_CASES 2장)으로 바꿔 끼운다
- 시·군·구로 합칠 때 구가 있는 일반 시의 구는 하나의 시로 합친다. 특별시·광역시의 구는 그대로 둔다
  - 합칠지는 이름이 아니라 코드로 정하고, 합친 시의 코드는 구 코드의 앞 4자리 + `0`이다 (예: 수원시 장안구 `41111` → 수원시 `41110`)
  - 이 규칙은 `src/lib`의 구 합치기 함수(`toMergedRegionCode`)로 두고 테스트한다. 지도 파일과 코드 목록 파일을 만들 때 이 함수를 쓴다
  - 자세한 조건과 예외(증평군, 태안군)는 [DATA_MODEL.md](DATA_MODEL.md) 3장을 따른다
- 지도 완성도(v0.4)에 쓸 넓이는 모양을 줄이기 전 원본으로 미리 계산해서 **넓이 파일(`public/data/areas.json`)에 따로** 넣어 둔다. 줄인 모양으로 재면 넓이가 조금 달라지기 때문이다
  - 지도 파일과 따로 두는 이유: 넓이는 v0.4의 지도 완성도에서만 쓰므로, 첫 화면 지도 파일을 가볍게 유지한다
- 전체 땅 넓이는 이 데이터에 있는 모든 시·군·구 넓이의 합이다 (섬 포함, PRD F-13)
- 줄인 뒤 파일 크기 목표: 시·군·구 1MB 이하
- 실제 크기 (2026-10-01판, 점 5%만 남김, `npm run data:build`로 만든 결과)

  | 파일 | 내용 | 크기 |
  |---|---|---|
  | `public/data/regions.topo.json` | 시·군·구 지도 (230개) | 157KB |
  | `public/data/dongs.topo.json` | 읍·면·동 지도 (3,559개) | 914KB |
  | `public/data/codes.json` | 코드와 이름 목록 | 229KB |
  | `public/data/areas.json` | 시·군·구별 넓이 | 4KB |
- CC BY 4.0 라이선스라 앱 화면 어딘가에 데이터 출처(통계청 SGIS, admdongkor)를 표시해야 한다. 화면 어디에 넣을지는 COMPONENT_SPEC.md에서 정한다
- IDEA.md 규칙에 따라 동네는 행정동 기준이다. 이 데이터도 행정동 기준이라 그대로 쓴다 (예: 법정동 "OO동"이 행정동 "OO1동", "OO2동"으로 나뉠 수 있다)

## 7. 환경 설정과 보안

### 환경 변수

| 이름 | 어디에 | 값 | 버전 |
|---|---|---|---|
| `NEXT_PUBLIC_API_URL` | 프런트 `.env.local` | 백엔드 주소. 개발: `http://localhost:8000` | v0.2 |
| `CORS_ORIGINS` | `backend/.env` | 백엔드를 부를 수 있는 화면 주소. 개발 기본값: `http://localhost:3000` | v0.2 |
| `DATABASE_URL` | `backend/.env` | Neon DB 주소. psycopg를 쓰므로 `postgresql+psycopg://`로 시작한다 | v0.3 |

- `NEXT_PUBLIC_`으로 시작하는 값은 브라우저에 그대로 보인다. 백엔드 주소만 넣고 비밀번호나 DB 주소는 절대 넣지 않는다
- DB 주소는 `backend/.env`의 `DATABASE_URL`에만 넣는다. 코드에 적거나 출력하지 않는다
- `.env` 파일들은 Git에 올리지 않는다 (`.gitignore`의 `.env*`가 `backend/.env`까지 막는다)

### 보안
- CORS는 `CORS_ORIGINS`에 적은 주소만 허락한다. 모든 주소(`*`)를 허락하지 않는다
- v2.0(로그인) 전에는 배포 주소를 알면 누구나 기록을 보고 고칠 수 있다. 그래서 연습용 기록만 넣는다

### 실행 방법 (이 PC)
- 이 PC는 `Scripts` 폴더의 `.exe` 실행이 막혀 있어서 `uvicorn`, `pytest`를 바로 부르지 못한다. 항상 `python -m` 형태로 실행한다
- 백엔드 서버 (`backend/`에서): `uv run python -m uvicorn app.main:app --reload --port 8000`
- 백엔드 테스트 (`backend/`에서): `uv run python -m pytest`
- v0.3 DB 표 적용 (`backend/`에서): `uv run python -m alembic upgrade head`

## 8. 백엔드 구현 메모 (API_SPEC을 지키려면)

FastAPI와 Pydantic의 기본 동작이 API_SPEC과 다른 곳이 있다. 아래처럼 맞춘다.

| 기본 동작 | API_SPEC | 맞추는 방법 |
|---|---|---|
| 검사 실패 시 `422`와 `{ "detail": [...] }` | `400`과 `{ "error": { code, message } }` | 검사 실패 에러를 잡는 처리기를 `main.py`에 두고 API_SPEC 모양으로 바꾼다. 처리하지 못한 예외는 `500 INTERNAL_ERROR`로 바꾸고 내부 내용을 넣지 않는다 |
| 모든 규칙을 한꺼번에 검사해서 에러를 여러 개 낸다 | 5장 순서대로 먼저 걸린 하나만 | Pydantic 모델은 **1단계(모양)만** 맡는다. 시작일은 모델에서 `str \| None`(빠져도 통과)으로 두고, 2~8단계는 `rules.py`의 함수가 순서대로 검사한다 |
| 모르는 필드를 조용히 버린다 | `INVALID_REQUEST` | 모델 설정에 `extra="forbid"` |
| 숫자 `123`을 글자로 바꿔 주기도 한다 | 타입이 틀리면 `INVALID_REQUEST` | 모델을 strict 모드로 둔다 |
| 이름은 파이썬 이름(snake_case) | JSON은 camelCase | 모델에 camelCase 별칭(alias)을 붙이고, 응답도 별칭으로 내보낸다. snake_case 이름(`start_date`)으로 받는 설정(`populate_by_name`)은 켜지 않는다. 켜면 모르는 필드가 통과한다 |
| 주소의 `id`를 `UUID` 타입으로 적으면 형식이 틀릴 때 `422` | 형식이 틀려도 `404 TRIP_NOT_FOUND` | `id`는 글자(`str`)로 받고 저장소에서 찾지 못하면 404 |
| 본문을 먼저 검사하고 함수에 들어온다 | 수정은 `id` 확인(0단계)이 내용 검사보다 먼저 | 수정 주소는 본문을 모델로 바로 받지 않는다. `id`를 먼저 찾은 뒤 본문 JSON을 읽어 검사한다 |
| 시각을 `2026-05-05T09:12:30.123456+00:00`처럼 쓴다 | `2026-05-05T09:12:30.000Z` (밀리초 3자리 + `Z`) | 응답에서 시각을 이 모양으로 바꿔 내보낸다 |

- **"지금 시각"과 "저장소", "코드 목록"은 의존성 주입으로 받는다.** 테스트에서 시각을 정해 주고(TEST_CASES 2장 기준 시각), 테스트마다 빈 저장소를 쓰고, 가짜 코드 목록을 넣기 위해서다
- **한국 시간은 파이썬 `zoneinfo`로 구한다.** Windows에는 시간대 정보가 없어서 `tzdata` 패키지를 함께 설치해야 한다
- **글자 수**: 파이썬 `len()`은 문자 하나를 1자로 세서 화면의 `countDiaryChars`, Postgres의 `char_length`와 같다
